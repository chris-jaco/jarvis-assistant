## 3–5. Registry, adapters, permission/confirmation design

Registry entries contain id/name/description/integration/capability/permission/schema/handler, optional confirm, timeout and non-mutating prepare/summarize. ToolAdapter describes hosted/MCP/API/function/local transport. Composition publishes descriptors automatically without frontend integration-specific code.

READ executes immediately. WRITE confirms by default with per-tool opt-out. SENSITIVE always confirms. Pending state is server-owned and session-scoped; it freezes resolved inputs, event ID and etag. Decisions are consumed synchronously before execution. One pending action, 60-second expiry, invalidation on unrelated speech/new tool/session end, max 100 invocations/session, 30-minute session lifetime. Duplicate call IDs share a cached result; rebinding a call ID is rejected. No automatic write retries.

Voice decisions only use a new user's transcription bound at speech start to that pending ID. Approval is armed after question playback ends; early yes cancels rather than executing. Old yes/no transcripts cannot decide a new action. Rejection and button fallback are available. No model-accessible confirmation tool exists. SDK native approval APIs were inspected; the custom backend layer avoids the documented Realtime pause that prevents new user requests during native approval.

## 6. Internet search

Backend sends one Responses request with hosted GA web_search, mandatory search, store:false, bounded hosted call/output limits, 25-second timeout. Returns concise answer, source metadata and retrieval time. Requires an actual completed search response; failures become safe categories, not invented current information. The browser has no permanent OpenAI key. No deprecated web_search_preview or beta Realtime endpoint was added.

## 7–9. Calendar, authentication and environment

Google Calendar official REST API plus google-auth-library was selected to avoid an unnecessary MCP service and give explicit OAuth/timezone/etag control. Supports list/upcoming/range, details, freeBusy/free intervals, create, move/update and delete. Ambiguous query matches fail before confirmation or mutation. Mutation approval binds a single event/occurrence and etag; a changed version fails closed. Series masters and moving all-day events are outside this version. No attendee/invitation integration.

Local setup:

1. Enable Calendar API in Google Cloud; configure consent/test user.
2. Create a Web application OAuth client with exact loopback redirect http://127.0.0.1:3001/oauth/callback.
3. Put client ID/secret and OpenAI key in local backend .env only; set USER_TIMEZONE and choose a private test calendar.
4. Run npm run google:authorize on the machine running the user's browser; open the printed consent URL.
5. Grant calendar.events/calendar.freebusy, then restart JARVIS.

Callback uses random state, PKCE S256, one-time consumption and five-minute expiry. Tokens are not returned to frontend; .local/google-tokens.json is ignored and created atomically with 0600 permissions, directory 0700 when created. Insecure/symlink token files are rejected. Refresh token is preserved when access tokens refresh. Revoke in the Google account and remove the private token file to disconnect. Testing-mode Google refresh token expiry may require reauthorization.

Environment: OPENAI_API_KEY; PORT/HOST; USER_TIMEZONE; OPENAI_SEARCH_MODEL; TOOL_CONFIRM_WRITES; optional GOOGLE_CLIENT_ID/GOOGLE_CLIENT_SECRET/GOOGLE_REDIRECT_URI/GOOGLE_CALENDAR_ID/GOOGLE_TOKEN_PATH. Exact placeholders/defaults are in .env.example. Missing Google config does not prevent startup, voice or search; missing OpenAI key prevents live voice/search but server and UI still start.

## 12. Exact manual local acceptance plan

Configure credentials and OAuth above; npm run dev, connect in local browser; check timezone/calendar. Do not test against important shared events.

A. “Hola Jarvis, ¿me escuchas?” — verify speech, transcript/states. Add “Me llamo Ana” then “¿Cómo me llamo?” for context.
B. “Jarvis, ¿qué pasó hoy con OpenAI?” — web.search success, current sourced answer; a search failure must say current information was unavailable.
C. “¿Qué tengo mañana?” — compare events and timezone with Google Calendar; no confirmation.
D. “¿Tengo algún hueco mañana por la tarde?” — if asked, specify 15:00–20:00; compare actual free slots.
E. “Agéndame una prueba de Jarvis mañana a las 18.” — supply “30 minutos” if duration is requested. With TOOL_CONFIRM_WRITES=true wait for the question; ensure nothing exists before confirmation. Say “Sí” after playback ends; one event 18:00–18:30. With false WRITE may proceed without confirmation.
F. “Mueve la prueba de Jarvis a las 18:30.” — keep 30 minutes, confirm under configured policy; verify one event 18:30–19:00. Duplicate matching titles must ask which, with no mutation.
G. “Elimina la prueba de Jarvis.” — supply tomorrow if requested. Explicit question with event/time is mandatory even with write confirmations disabled. Check it exists before “Sí”; then verify deletion. Repeating yes cannot delete again.
H. Create another test event, request deletion, say “No.” Verify it remains. Also test >60-second expiry and unrelated new request followed by yes: no old action executes.
I. Ask a long question and interrupt naturally: “Para, responde en una frase.” Verify V0.1 barge-in and Interrumpir button, then disconnect/reconnect and confirm microphone/context cleanup.

Repeat with production: stop dev, npm run build, npm start. Additional microphone denial, missing Calendar, token/asset privacy, network loss and disconnect-during-connect tests are detailed in README.

## 13–15. Limitations, security and latency

Live OpenAI requests, Calendar OAuth/refresh/API access and physical audio/VAD/barge-in were not exercised here: no real credentials/browser microphone are available. Automated/HTTP readiness is verified; full live acceptance remains outstanding. Current official API websites were blocked by proxy 403; current official OpenAI SDK source/docs and Google auth source/API discovery were fetched on GitHub. Sources and supported API decisions are linked in README.

One personal local session per browser, no multiuser authentication or public deployment. HttpOnly/SameSite and origin/JSON checks do not authenticate a remote user or protect against local malware. OAuth tokens are private plaintext files, not encrypted OS keychain storage. Only use loopback/trusted host until separate authentication/deployment hardening. Tool outputs go to OpenAI for voice synthesis as part of the requested functionality; telemetry excludes private contents. Sources and MCP data are untrusted; confirmations reduce prompt-injection consequences but do not eliminate them. Strict voice matching can require button fallback. The client clock is advisory for UI; server expiry is authoritative. Session midnight/date changes may require reconnecting to refresh clock context.

No live latency figures are claimed. Tool duration includes human approval wait. Search adds Responses followed by Realtime synthesis; Calendar may need token refresh and GET resolution before mutation. UI polls once/second; one HTTP tool operation per session prevents overlapping mutations. SDK bundle warning remains; measured main gzip bundle is ~268.9 kB versus baseline ~266.9 kB, a ~2 kB increase. No audio/VAD rewrite or speculative performance tradeoff.
